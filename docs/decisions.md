# Decision log — causal-presidents

Every decision that shapes the analysis, with its status. Written so that a reader can tell
*why* each choice was made, and so that a later reversal is visible rather than silent.

Status values: **LOCKED** (base spec, not to be changed) · **DECIDED** (this project) ·
**VERIFIED** (empirically confirmed) · **OPEN** (unresolved) · **SUPERSEDED**.

## Stage 3 — validation and quality gates — built 2026-10-11

PHASES.md calls this "the honesty chokepoint": Stage 8's limitations section is largely written from
its output. Five gates, configured entirely in `analysis/specs/quality.yml` and implemented in
`ingestion/quality/gates.py`, run over every landed series. **88 series gated: 60 `ok`, 28 `flagged`,
0 `empty`.**

| # | Decision | Status | Date | Reason |
|---|---|---|---|---|
| Q-01 | Gates are evaluated **inside the study window only** (`1999-01-01` → open) | DECIDED | 2026-10-11 | Scanning a series' whole history fires on 1961→1962 (+2039%) in `gdp_growth` and on pre-1999 volatility in five more series (C-06, C-21). Noise in a quality report is worse than an absent gate, because it teaches the reader to ignore flags |
| Q-02 | Every gate parameter lives in the spec, never in code — thresholds, grains, resample rules, breaks, adjudications | DECIDED | 2026-10-11 | A gate result must be reproducible from the spec plus the raw payload. Anything decided inside the gate code is an unexplained number |
| Q-03 | The spike gate uses **two measures**: `relative` (`\|Δ/value\| > 50%`) for level series, `points` (`\|Δ\| > 10pp`) for series already expressed as a percentage | DECIDED | 2026-10-11 | Found by running it: one 50%-relative rule across 88 series flagged **52**, because a growth rate moving 0.5%→3.0% is a 500% relative change and a 2.5-point move. Over-flagging does not merely annoy — it hides the real problems in the flood |
| Q-04 | Only **adjacent** periods are compared for spikes | DECIDED | 2026-10-11 | The Stage 2 provisional gate zipped consecutive *observed* periods, so a hole turned a multi-year level change into a single reported "spike" — 2000 vs 2004 reported as a one-year move |
| Q-05 | A flagged spike is **adjudicated** in the spec against one of four verdicts, and an unadjudicated flag is printed as such | DECIDED | 2026-10-11 | The gate cannot tell a data error from a real event and must not pretend to. There is no path where a flag disappears without a reason attached. **60 of 67 spikes are deliberately left unadjudicated** — no documented cause was found for the immunisation and primary-completion swings, and inventing six plausible reasons would defeat the field |
| Q-06 | The Brent daily→monthly rule is **frozen as a declared input**: `mean_of_daily_observations` | DECIDED | 2026-10-11 | PHASES.md Stage 2 requires it frozen "because changing it later changes every adjusted estimate". Chosen over month-end (an arbitrary single day, and exactly the quote a holiday removes) and over the sum (which scales with trading days, not price level). Stage 4 must reuse it, not re-choose it |
| Q-07 | The revision gate distinguishes **new series** from **revised values** | DECIDED | 2026-10-11 | The World Bank catalogue grew from 15 to 22 datasets between the two vintages. Reporting seven additions as seven revisions would be wrong; at Stage 3 no series present in both vintages has a revised value |
| Q-08 | The Stage 3 exit criterion is **enforced in code**: a series in a manifest with no gate result fails the run | DECIDED | 2026-10-11 | "No series reaches Stage 4 without a gate result" is only true if nothing is omitted. A silent omission is the exact failure this check exists for |
