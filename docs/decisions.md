# Decision log — causal-presidents

Every decision that shapes the analysis, with its status. Written so that a reader can tell
*why* each choice was made, and so that a later reversal is visible rather than silent.

Status values: **LOCKED** (base spec, not to be changed) · **DECIDED** (this project) ·
**VERIFIED** (empirically confirmed) · **OPEN** (unresolved) · **SUPERSEDED**.

## The app layer (Stage 9) — built 2026-10-21

The registry is the app's data contract (Stage 8). These are the decisions about the thing that renders it.
The framework question was reopened deliberately on 2026-10-21 — "must it be Streamlit?" — and settled
with the costs written down rather than assumed away.

| # | Decision | Status | Date | Reason |
|---|---|---|---|---|
| UI-01 | **Streamlit 1.60** is the app framework | DECIDED | 2026-10-21 | It is the only option whose test harness renders the real app **without a browser**: `streamlit.testing.v1.AppTest` returns the element tree in pure Python, which is what makes the 36-card contract check cheap enough to run inside `scripts/verify.sh` and CI. Dash, Shiny and React all need a Selenium/Playwright driver, and neither is installed on this machine — the check would have become "run it when someone remembers", which is the failure mode C-42 recorded. Secondary reasons: one Python process with no build step or API layer (M-08's no-model-at-render-time rule is trivial to enforce), the page is a pure function of the registry so the rerun model has nothing to desynchronise, and the chat tab Stage 9b needs (streaming, session state, an input box) is native |
| UI-02 | **Read-only before chat** | DECIDED | 2026-10-21 | Out-of-scope refusal measures **0.25** (Stage 8c): a forecast about a covered outcome is not refused by similarity alone. Shipping the chat tab now would produce the failure the corpus exists to prevent — a confident answer to a question this data cannot answer. The tab follows an intent gate and a re-measurement on the declared eval set |
| UI-03 | The app reads `registry/dags/` and **nothing else** — no database, network or fitting library — and `tests/verify_app.py` enforces it by scanning the source for those imports | DECIDED | 2026-10-21 | Restates M-08 for the one component a reader touches directly. A grep is a weaker guarantee than a sandbox but a stronger one than a promise |
| UI-04 | The page states **the ratio (2 of 36 cards carry a number) before any single number** | DECIDED | 2026-10-21 | A reader who opens one card otherwise cannot tell whether the project estimated two things or failed to estimate thirty-four. | UI-05 | Known costs of Streamlit, accepted: **no URL routing** (a card cannot be linked), coarse layout control, and the graph is a static SVG rather than a clickable object | DECIDED | 2026-10-21 | Each is cheap to live with for a reading artifact and each has a named fix if it starts to hurt: `st.query_params` for linkable cards (planned), a component for node interaction. | UI-06 | Alternatives considered and rejected **for now**, with the condition that would revive each | DECIDED | 2026-10-21 | **Static export** (Quarto/Jinja → Pages): buys real URLs, typography and no server, but kills the chat tab and turns every vintage into a rebuild — right if the deliverable becomes "publish a page" rather than "run an app". **Plotly Dash**: callbacks without full reruns and real interactive graphs, but a Flask server plus a browser driver for tests, for a page that needs neither. **FastAPI + Svelte/React**: total control, two languages, a build toolchain and Playwright for verification — right if someone else maintains it as a product. **Shiny (R or Python)**: keeps the analysis language, but the registry is already Python-readable and the test harness is still browser-based. **Panel/NiceGUI/Reflex**: new ecosystems for a page that needs columns and tabs |

## Stage 8g - describing a tenure, and the estimate between presidents - 2026-10-27

| # | Decision | Status | Date | Reason |
|---|---|---|---|---|
| T-01 | A tenure is described by its **deviation from a tenure-blind LOESS trend**, not by a tenure mean and not by interrupted time series | DECIDED | 2026-10-27 | A tenure mean compares the calendar: the series trend throughout the window. ITS is a quasi-experimental design whose coefficients are effects (Wagner 2002; Bernal 2017) and would smuggle the causal claim back in under a descriptive label |
| T-02 | The uncertainty reported is the **range across three declared spans**, never a confidence interval | DECIDED | 2026-10-27 | The quantity that varies here is an analyst choice, not sampling. A CI would imply a model of the counterfactual this stage does not have - and a bootstrap of break dates was considered for the changepoint stage and dropped for the same reason |
| T-03 | The estimate between presidents is the **difference of two tenure deviations**, in outcome units | DECIDED | 2026-10-27 | It is the strongest comparison this data supports with the fewest assumptions: no parallel trends, no ignorability, no counterfactual. Its only assumption is that the smoother is a fair description of the long-run path |
| T-04 | A tenure with **fewer than three native points** publishes "insufficient points", not a deviation | DECIDED | 2026-10-27 | The preview showed a two-year administration on an annual series holding two points, where a mean of two residuals describes the smoother rather than the window |
